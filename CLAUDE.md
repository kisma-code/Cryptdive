# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Cryptdive** (formerly "Pixel Depths"): a portrait, phone-only pixel-art action RPG (auto-attack, floors with stairs, level-up upgrades), shipped as a PWA on GitHub Pages: https://kisma-code.github.io/Cryptdive/ (the path is case-sensitive; the repo was renamed from `First-Web-Game`). Plain HTML/CSS/JS with no build step, no package.json, no linter and no test suite.

## Commands

```sh
python3 -m http.server 8123        # run locally, then open http://localhost:8123/
node --check game.js               # syntax check (also sw.js)
node --input-type=module --check < auth.js   # auth.js is an ES module
```

Testing is done with ad-hoc Playwright scripts (Chromium is preinstalled; `require('playwright')` works) using `devices['iPhone 13']`. Touch input is sent with CDP `Input.dispatchTouchEvent`. `game.js` exposes a read-only test hook, `window.__pd` (state, floor, player, enemies, stairs, fx counts). Put scripts in the scratchpad, not in the repo. Login is required (the Firebase config is filled in) and gstatic is not reachable from the sandbox, so tests must serve fake `firebase-app.js` / `firebase-auth.js` / `firebase-firestore.js` modules with `context.route('https://www.gstatic.com/firebasejs/**', …)`, block service workers, and tap `#btnGoogle` before `#btnStart`. To test a deep floor, serve a test-only copy of `game.js` with `context.route('**/game.js', …)` that replaces `floor = 1; kills = 0; pendingLevels = 0;` in `newGame()` (the same trick can expose `genRoom()` to check many generated maps); never ship such a hook, because the leaderboard trusts the client. To test in-app browsers (LINE, Instagram), create the context with a `userAgent` that contains `Line/…` or `Instagram`.

## Deploying

GitHub Pages serves `main` from the repo root (`.nojekyll` is present). Work goes on a branch, then a PR; merging deploys in about 1 minute. **Bump `VERSION` in `sw.js` for every change to a shipped file**; phones keep old files otherwise. The service worker is network-first for same-origin files, cache-first only for the fixed-version Firebase SDK on gstatic, and it never intercepts other cross-origin requests (login, Firestore). After an update takes control, `game.js` reloads the page once, but not during a run.

## Architecture

- `game.js`: the whole game in one IIFE, split by `// ---------- Name ----------` section comments. Main loop: `frame()` → `update(dt)` (logic runs only when `state === 'play'`, or for effects when `'dying'`) → `render(dt)` → `updateHud()`. States: `title | play | levelup | paused | dying | over`. Overlay screens are DOM elements in `index.html`, shown or hidden with the `.hidden` class.
- **Rendering:** draws straight to the full-resolution canvas with `setTransform(R, …)`. `R` is a whole number of device pixels per game pixel (about 160 game px across the screen), so sprites stay sharp while positions snap to device pixels (`snap()`) for smooth motion. Do not go back to a low-res offscreen canvas that is scaled up; that made motion look jumpy.
- **Pixel art:** sprites are string grids drawn by `sprite(rows, swap)` from the `PAL` color map (one letter = one color; `.` = transparent). Each sprite also gets a white silhouette for hit flashes.
- **Draw order matters:** room `bg` canvas → `drawWater()` → stairs/pickups → characters (sorted by y) → normal particles → torch brackets → `drawDarkness()` (darkness layer with light holes from `collectLights()`) → `drawLavaGlow()` → torch flames → `drawCandles()` → weapon fx (additive `lighter` blending) → additive particles → `drawAnimeFx()` → damage numbers → stairs arrow. Anything that must glow goes after the darkness. A new light source also needs an `addLight()` call in `collectLights()`.
- **Weapons:** the `WEAPONS` table holds base stats (copied to `p.w`) and 2 unique `ups` each. Only one weapon per run. Weapon logic and effects: `updateWeapon` / `fire*` / `update*` and `drawWeaponFx`. All damage goes through `hurtEnemy()` (crits, hit sparks, damage numbers, knockback, kill).
- **Laser beams:** beam 1 aims at the target, and the other beams are spaced evenly around the hero (`2π / beams`: 2 = opposite, 4 = a cross); More Beams goes up to 6.
- **Upgrades:** `UPGRADES` is the general list (`apply(p)`); weapon `ups` use `apply(w)`. `openLevelUp()` mixes both and always offers at least 1 weapon upgrade. **Do not add options that repeat the same idea** (the owner asked twice): Damage and Attack Speed exist only in the general list. Attack Speed lowers `w.cd` down to each weapon's `minCd`. Each upgrade has a `pic` (a 12x12 pixel icon in `ICONS`, drawn with `iconCanvas()`) and a `tag` value sign (a string, or a function of `w` that uses `pct()` for "bigger" upgrades); a new upgrade needs both. The level-up cards slide in one by one (`cardIn` in `style.css`), and they are enabled after 500 ms. Weapons: Laser Beam, Chain Lightning, Boomerang (replaced Orbit Blades; `weaponFix()` maps an old saved `'blades'` to `'boomerang'`), Fire Rockets.
- **Classes and Souls:** the 4 weapons are the 4 classes (the select screen says SELECT CLASS; tapping a class opens `#scrClass`, where Souls buy permanent upgrades, then PLAY). `classes` holds, per weapon id, `souls`, `earned` (total ever), `atk`/`spd`/`hp` levels (no max; cost `classCost(lvl) = 5 + 3 * lvl`; +10% damage, +5% attack speed down to `minCd`, +2 max HP per level, applied in `makePlayer()`) and `best` (the class best floor). `giveSouls()` pays once per run (game over or quit): `floorSouls(floor - 1)` for the completed floors (1 Soul per floor, +1 for every 5 floors deep) + 5 per boss killed. **Fast floors:** a non-boss floor below the class best at the start of the run (`runBest`) spawns only 1 elite monster (`elite`, 3x HP, gold glow and bar) with all the EXP of the floor (`fl.fastXp`). Saved in `localStorage` (`pixelDepths.classes`) and in the cloud field `classes` (a second write after the run save; `mergeClasses()` keeps, per class, the record with more `earned`).
- **Monster type ids are legacy names:** `slime` = Zombie, `bat` = Imp, `skel` = Skeleton Warrior, `boss` = Horned Demon. Common deeper monsters: `archer` = Skeleton Archer (floor 6+), `ghost` = Ghost (floor 8+). Area monsters: `sewer` = Sewer Slime (splits into 2 small ones), `fireimp` = Fire Imp, `knight` = Bone Knight (stops, then charges), `wraith` = Frost Wraith (3 bolts), `bloater` = Spore Bloater (swells, then bursts near the hero), `phantom` = Phantom (fades out, appears near the hero; cannot touch while faded), `leech` = Blood Leech (hops), `golem` = Ember Golem (ring of 6 fireballs), `eye` = Void Eye (homing orb). Bosses (`boss: true` in `ETYPES`; use `isBoss(e)`, never `type === 'boss'`) take turns on every 5th floor from `BOSSES`: Horned Demon (calls zombies), `lich` = Bone Lich (rings of 8 bolts, calls skeletons), `brute` = Plague Brute (charges). Special moves of the newer monsters are in `monsterMove()`. `fly: true` means water and ice do not change its speed; `shoot: true` means it keeps distance and shoots when it can see the hero (`los()`). Monster bullets: `shots`, `fireShot()` / `updateShots()` / `drawShots()` (slow, stop at walls, drawn after the darkness). Monster HP: `1 + 0.3 * (floor - 1) + 0.013 * (floor - 1)^2` times the base.
- **Areas and rooms:** `AREAS` changes every 5 floors (Crypt → Flooded Sewer → Lava Caves → Bone Cathedral → Frozen Catacombs → Fungal Hollow → Haunted Library → Blood Marsh → Obsidian Forge → Abyss Gate, then repeats after floor 50). Each area has a theme, its room shapes (`rect`, `cross`, `L`, `ring`, `cave`, `hall`, `library`) and 1 extra monster. Pools per area are set in `genRoom()` (water: sewer, fungal, marsh; ice: frost; lava: lava, forge, abyss "void" with `theme.glow`). Fungal Hollow has glowing mushrooms (`shrooms`, `drawShrooms()`). `genRoom()` picks a size from `SIZES`, so `ROOM_W`/`ROOM_H`/`RW`/`RH` are variables, and the hero starts at `spawn` (not the room center). Map tiles: `T_FLOOR`, `T_WALL`, `T_WATER` (slows), `T_LAVA` (hurts the hero), `T_ICE` (25% faster). `genRoom()` walls off unreachable tiles, and `addPools()` never lets lava cut off floor. `freeSpot()` returns only plain floor. Monsters walk around walls with a BFS distance map from the hero's tile (`updateFlow()` / `steer()`). The boss is wider than 1 tile, so it uses "big nodes" (2x2 open blocks; `updateBigFlow()` / `steerBig()`), and boss floors (every 5th) are made boss-safe: no `cave` or `library` shape, pillars keep a 2-tile gap, `fillBossGaps()` walls off any tile not inside a reachable 2x2 block, and `bossSpot()` spawns the boss where it fits.
- **Controls:** a fixed joystick at the bottom middle; the touch zone is the bottom 45%. It has no dead zone and full speed from any push (the knob sets only the direction), and the hero's velocity is set at once (no easing). The camera locks to the hero (a delayed camera felt like "dragging") and is not clamped to the room, so the hero always stays in the middle of the play area (between the HUD and the joystick), also at room edges. On a computer with no touch screen (`DESKTOP`: no coarse pointer and no touch points), the `desktop` class on `<html>` hides the joystick and touch zone, the play area goes down to the bottom, and the title says "Use WASD to move." The keyboard uses `e.code` (WASD / arrows to move, Esc or P to pause and resume) on all devices; keys are cleared on window blur.
- **Login and cloud save:** `auth.js` (ES module) loads the Firebase SDK 10.12.2 from gstatic and talks to the game through two globals: `window.PD_CLOUD` (provided by auth.js: `showLogin`, `saveRun`, `saveBest`, `openBoard`, `user`, `required`) and `window.pdGame` (provided by game.js: `getBest`, `setBest`, `setWeapon`). Sign-in uses `signInWithPopup` only; **do not add `signInWithRedirect`** (it fails with "missing initial state" on iOS Safari and when a link opened in another app jumps to Safari, because the auth domain is `firebaseapp.com`). In-app browsers (LINE, Instagram, Facebook, …; detected by user agent) cannot sign in with Google: LINE is sent to the normal browser with `?openExternalBrowser=1` (removed again from the address afterwards); others see a note with COPY LINK. Login is required when `firebase-config.js` is filled in; while its `apiKey` starts with `PASTE`, the game runs in guest mode. Firestore collection `players/{uid}` holds `name` (first name only; the email stays only in Firebase Authentication, where the owner can see it, as the login screen says), `bestFloor`, `bestLevel`, `bestKills`, `weapon`, `runs`, `classes`, `updatedAt`. `firestore.rules` allows only exactly these fields, and `bestFloor` may only go up, so **a change to the saved fields needs the same change in `firestore.rules`**, which the owner must paste into the Firebase console (project `pixel-roguelike-web-game`). The Firebase config values are public by design.
- **CrazyGames build:** `python3 tools/build-crazygames.py` makes 4 flat files in `dist/crazygames/` (git-ignored: `index.html`, `game.js`, `style.css`, `crazygames.js`) to drag and drop into the CrazyGames upload zone (it does not accept zip files). **Ads are not allowed in Basic Launch**, so the default build has no ad button; `--ads` adds `window.PD_CG_ADS = true` for Full Launch. A failed ad hides the button for the session (`adFailed`). Its `index.html` is made from `index.html` (no `auth.js`, no manifest, no Apple metas) and loads the CrazyGames SDK v3 (`https://sdk.crazygames.com/crazygames-sdk-v3.js`), then `crazygames.js`, which runs `SDK.init()` (6 s timeout), sets `window.PD_PLATFORM = 'crazygames'` and `window.PD_CG` (`storage` = the SDK Data module when it works, else `localStorage`; `adsReady`; `gameplayStart/Stop`; `rewardedAd`), and only then loads `game.js`. In `game.js`, `CG` is non-null only there: `store` uses `CG.storage`; `frame()` sends gameplayStart/Stop when `state` enters or leaves play; the game-over screen shows `#btnAdSouls` (rewarded ad: double the run's Souls, once per run; sound suspended during the ad via `setAdAudio()`); no service worker, no install hints, no privacy link (`.platform-crazygames`), no login and no leaderboard (they stay hidden without `auth.js`). CrazyGames progress is separate from the web version. The docs host docs.crazygames.com is not reachable from this sandbox; the SDK API was checked through web search. Test the build by serving `dist/crazygames/` and faking `sdk.crazygames.com` with `context.route`.
- `privacy.html`: the privacy policy (standalone page with inline styles, linked from the title and login screens; it is in the service worker `FILES`). **Update it when the saved data, the login or ads change.** The contact email is in `#contact`.
- `localStorage` keys (they keep the old name on purpose, so progress is not lost): `pixelDepths.bestFloor`, `pixelDepths.mute`, `pixelDepths.weapon`, `pixelDepths.classes` (all access wrapped in try/catch via `store`).

## Working with the owner

- The owner plays on an iPhone (Safari and the Home Screen app) and checks changes on the live site after each merge.
- Reply in ASD-STE100 (Simplified Technical English): short, simple sentences.
- Ask clarifying questions before you build a new feature or make a vague change. The owner wants this.
- Make a PR for each change; the owner merges it. Before you start, check whether the previous PR is merged (`git fetch origin` and a fast-forward of the work branch) and start from the latest `main`.
- Design rules from the owner: keep the pixel look and monospace font (the glass/iOS-font theme was rejected and reverted); dark gothic dungeon (original art, not a copy of any existing game); no rings around the hero on attack; no hit stop; no full-screen or fast flashing effects (photosensitive safety).
